Transaction-count accuracy treats every order equally; value-weighted accuracy weights order-level correctness by rupee amount instead (it measures decision correctness, not that money was physically verified moving). False-clear = confidently wrong (matched when it should have been an exception, the dangerous failure). Safe-miss = conservative (flagged as an exception when it should have matched, money just sits reviewable instead of moving wrong).

Validation & robustness

Accuracy across corruption levels

Runs fresh batches at increasing corruption rates (not the same batch shown above), several independent seeds per rate averaged together with the spread shown, so the accuracy number isn't just true for one cherry-picked run.

Validation & robustness

Confidence threshold calibration

The AI confidence threshold (default 0.6) is a starting point, not an empirically justified one. This sweeps the auto-accept bar across a range of values against one fixed batch and one fixed round of LLM verdicts — only the accept/reject line moves — so the default can be defended with a number instead of asserted.
